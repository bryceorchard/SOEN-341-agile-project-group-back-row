- **Correctness issues (verified with Node, TZ=America/Toronto):**
  - `created_at` is SQLite `datetime('now')` (UTC, `YYYY-MM-DD HH:MM:SS`, no `Z`). `new Date()` reads it as
    local time, so in Montréal every notification is placed 5 h in the future. "Relative time" shows
    "just now" for the first 5 h and runs 5 h behind after that.
  - The deadline is a `type="date"` string. `new Date('2026-11-18')` is UTC midnight, so no reminder fires
    on the "Apply by" day itself (7 pm the evening before, Montréal time). A posting with today as its
    deadline never gets a reminder.
  - The deadline is free text in the API (`optionalText`). An unparseable deadline gives `NaN`, which fails
    both `< 0` and `> 3`, so the posting **is** treated as inside the window.
  - `NotificationService` subscribes with no `error` handler. Failed polls (backend down, expired token)
    surface as unhandled errors every 60 s. This is also the root cause of the CI failure.
- **Smaller points:** the generator scans every job in the DB and runs an N+1 query on every GET by any
  user (a write inside a GET). It could be scoped to the requesting user. The list shows the empty state
  before the first load completes. Notification cards are clickable `<div>`s with no keyboard or role
  support. The unread count is not reset on logout. `app.ts` constructor indentation is broken.
  Several files have no trailing newline.
