- **Bug (reproduced):** `PUT /resumes/:id` (`routes/resumes.js:76`) replaces the file but keeps the resume
  id, and nothing clears `resume_feedback`. After a replace, `GET /resumes/:id/feedback` still returns the
  feedback for the old file. A throwaway Supertest script confirmed this. The fix is to delete the
  feedback row in the PUT handler (or compare `uploaded_at`), and add a test for it.
- **Should fix:**
  - If `AI_API_KEY` is missing, the provider silently falls back to the mock (`provider.js:63`). In a real
    deployment, every user would then get the same canned feedback for a fictional resume, stored with
    `model: 'mock'`. It would be safer to use the mock only when it is opted into explicitly (for example
    `NODE_ENV=test` or `AI_PROVIDER=mock`), and to return 503 otherwise.
  - Production code loads its mock reply from `test/fixtures/ai/sample-feedback.json` (`provider.js:11`).
    The mock reply should live under `src/ai/`, so `src` does not depend on the test folder.
- **Minor:**
  - A 2xx provider response with a body that is not JSON makes `res.json()` (`provider.js:54`) throw a
    SyntaxError, which becomes a 500 instead of a 502.
  - If the stored file is missing on disk, `readFile` throws outside the try block in `extract-text.js`,
    which gives a 500. The `/file` route returns 404 in the same situation.
  - The real `fetch` path (non-2xx → 503, timeout → 503) has no tests. The 503 test injects a provider
    that throws, so the error mapping inside `callOpenAiCompatible` is never exercised. Stubbing
    `globalThis.fetch` would cover it without any network access.
  - `diApi._setReply` patches the Supertest agent. A closure-held variable would be cleaner.
- **Looks good:** owner-only access returns 404 rather than leaking existence; the rate limit is checked
  after the ownership check and before extraction; failures save nothing; the upsert keeps one row per
  resume; `ON DELETE CASCADE` cleans up on resume delete; and the tests make no network calls.
- `npm audit` reports 3 issues (body-parser, multer, qs), but they are all on `main` already. This PR
  does not introduce them.
